# CODE_STYLE.md — Стиль кода

Единый источник правды по стилю кода проекта. Документ рассчитан и на **людей**, и на **ИИ-агентов** — правила одинаковы для всех.

## Общие принципы

- **C++20**, MSVC (toolset v143), платформа **Win32**.
- **Без внешних зависимостей** — только WinAPI и стандартная библиотека.
- **Без PCH** — каждый файл включает только то, что использует сам.
- Код обязан собираться **без ошибок и без предупреждений** (включая анализатор MSVC).
- Идентификаторы — на **английском**, комментарии и UI-строки — на **русском**.

## Форматирование

- Скобки **Allman**: открывающая скобка с новой строки.
- Отступ — **4 пробела** (без табов).
- Длина строки — ориентировочно **до 120 символов**.
- Пустая строка между логическими блоками (группами операторов, функциями).
- Заголовочные файлы начинаются с `#pragma once`.
- Тело `case` в `switch` может оборачиваться в скобки.

```cpp
void Example()
{
    if (condition)
    {
        DoSomething();
    }
    else
    {
        DoOther();
    }
}
```

## Именование

| Что | Стиль | Пример |
|---|---|---|
| Типы (class/struct/enum) | PascalCase | `Figure`, `KeyBindings`, `Colors` |
| Функции и методы | PascalCase | `CreateGameField`, `SetPosition` |
| Локальные переменные | camelCase | `idFigure`, `currentScore` |
| Глобальные переменные | `g_` + camelCase | `g_console`, `g_bindings` |
| Компиляционные константы | UPPER_SNAKE_CASE | `MAX_FALL_LINES`, `LEVEL_TIME_STEP` |
| `constexpr`-данные в заголовках | `k` + PascalCase | `kSettingsFileName`, `kBindingKeys` |
| Члены `enum class` | UPPER_SNAKE_CASE | `KeyCodes::LEFT_ARROW`, `Colors::CYAN` |

- Все перечисления — `enum class` (закрытые).
- Базовый тип `enum class` указывается явно, если нужен (`: uint8_t`, `: unsigned char`).

## Заголовочные файлы

- `#pragma once` в начале.
- Порядок групп инклюдов (разделяются пустыми строками):
  1. стандартная библиотека (`<cstddef>`, `<string>`, ...);
  2. Windows (`<windows.h>`, `<conio.h>`, ...);
  3. заголовки проекта (`"Keys.h"`, ...).
  В `.cpp`-файлах заголовки проекта идут первыми.
- `Keys.h` и `Settings.h` — **header-only**: всё, что в них объявлено, должно быть `inline` / `constexpr` (или `static` для локальных данных).
- Код проекта в заголовках — в `namespace Tetris`.
- `std::size_t` требует явного `#include <cstddef>`.

## Типы и приведения

- Только `static_cast` / `const_cast` / `reinterpret_cast`. **Без C-стиля** приведений вида `(int)x`.
- `const`-корректность: методы, не изменяющие объект, — `const`; параметры-«вход» — `const T&`.
- `noexcept` для функций, которые не бросают исключений.
- Конструктор по умолчанию — `= default`.
- Инициализация членов: список инициализации в конструкторе + инициализация в классе (`int id{};`, `Colors color{ Colors::WHITE };`).
- Локальные массивы и структуры — нулевая инициализация `= {}` / `{}`.
- `auto` — для лямбд и итераторов, когда тип очевиден.

## Комментарии

- На **русском**, стиль `//`.
- Обосновывают **почему** и ключевые решения, а не пересказывают код.
- Неочевидные места (обходы ограничений WinAPI, битовые маски, инварианты) — обязательно комментируются.

## Обработка ошибок

- Фатальные ошибки — `MyErrorExit(сообщение)`.
- Операции, которые могут не удалиться, возвращают `bool`.
- Ошибки WinAPI не проглатываются без проверки.

## Консоль и строки

- Вывод в игру — только `std::wcout` и `wchar_t` (консоль в unicode-режиме).
- Строковые литералы — `L"..."`.
- Не использовать `printf`/`cout` для игрового вывода.
- Поле — 80×25, шрифт высотой 24 (см. инварианты в `AGENTS.md`).

## Предупреждения анализатора

- Намеренно отбрасываемое возвращаемое значение — явное приведение `(void)вызов();` с комментарием.
- **Не** использовать `#pragma warning(disable: ...)` для подавления C6031 и подобных.

```cpp
// _getch() вызывается ради побочного эффекта (чистка буфера),
// возвращаемый символ намеренно отбрасываем.
(void)_getch();
```
