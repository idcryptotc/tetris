## 2. Отложенные

### Заставка в маленьком окне (Adaptive)

При окне < 80×25 заставка урезана: логотип и ряд фигур не помещаются, заставка выглядит обрезанной. Подсказка `MessageBoxW` показывается, само игровое поле рисуется корректно (кадр обрезается справа/снизу). Не критично — отложено. Варианты: упрощённая заставка для узкого окна (только логотип в уменьшенном масштабе) или пропуск заставки при маленьком окне.

### Масштабирование кадра

Целочисленное масштабирование по ячейкам (2×, 3×: каждый логический пиксель — блок N×N из `█`; прецедент — логотип заставки с `scale = 2`) возможно и дёшево, но откладываем: либо лишнее, либо рано. Дробное масштабирование в текстовой консоли невозможно; масштаб шрифта — только в conhost (мы и так сами ставим 24px). Если делать — отдельным шагом: меняет и текст (счёт, подсказки), и рассинхронизирует меню (пишется мимо `ViewGameField`).

### Truecolor в Fixed (conhost)

Truecolor (24-бит, VT `\x1b[38;2;R;G;Bm`) введён только для Adaptive (Windows Terminal): в `ProgramSettings()` VT включается и флаг `g_console.truecolor` ставится только для Adaptive. В Fixed (conhost) truecolor не работает — 16-цветный путь через `SetConsoleTextAttribute` остаётся как есть. Причина: конвейер Fixed идёт через двойную буферизацию (`CHAR_INFO` хранит только 16-цветные атрибуты, 24-бит в копии между буферами не удержится) — этот путь для truecolor придётся переделывать. Отложено: сначала отработаем truecolor в WT.

### Меню глифами (пиксельный шрифт)

Меню (заголовок и пункты) планируется перевести на пиксельный шрифт (глифы) — как логотип заставки, в truecolor. Отдельная задача (отложена): нужен набор глифов для букв меню, отрисовка пунктов и навигация. Если пункты оставим на русском — потребуются кириллические глифы (значительно больше); вариант — перевести пункты на английский и переиспользовать латиницу из экранов Game Over/You Win. Пока меню остаётся текстовым.

## 3. Оставлено про запас (диагностика)

### Диагностические флаги

`--adaptive`/`--fixed`/`--diag` в `ProgramSettings()` (`Console.cpp`): ручное переопределение режима и диагностика в `tetris_diag.log` (рядом с exe) — `WT_SESSION`, `TERM_PROGRAM`, класс окна консоли, процесс-владелец окна, итоговый режим. Добавлены для проверки Adaptive-пути. Решение: оставить про запас (полезно для отладки и ручного переключения режима), убрать на более поздних этапах.
