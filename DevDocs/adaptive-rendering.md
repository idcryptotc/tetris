# Адаптивный рендер для Windows Terminal (conpty)

**Статус:** готово (2026-10-26, коммит `3b564ec`). Обновление: в Adaptive включена двойная буферизация (см. решение 2) — кадр появляется атомарно, без «рулона» и мерцания; проверено в WT (заставка, игровой цикл, ресайз). Игра в Adaptive рендерится truecolor (решение 7). Стартовое мерцание в Fixed устранено (решение 3).

## Проблема

Строка `system("mode con cols=80 lines=25")` в Windows 11 в Windows Terminal не работает (в консоли Win10 — работает). Терминал содержит вкладки, его размер меняется пользователем; запретить ресайз окна и убрать вкладки из кода приложения нельзя (окно принадлежит хосту). Принудительно сменить хост (например, в conhost) из кода тоже нельзя — это настройка ОС («Терминал по умолчанию»).

## Решение

Два режима (`ConsoleMode`), выбор — рантайм-детект conpty-хоста (не по версии ОС: WT есть на Win10, conhost — на Win11):

- **Fixed** — исходное поведение: `mode con cols=80 lines=25`, шрифт 24px, двойная буферизация. Win10/conhost — без изменений.
- **Adaptive** — conpty-хосты (Windows Terminal, терминал VS Code и т.п.): размер и шрифт не трогаем (управляет терминал), кадр 80×25 центрируется в реальном буфере, двойная буферизация (кадр рисуется в скрытый буфер, атомарное переключение).

Объём: игровая логика, меню и заставка не менялись (заставка идёт через `ViewGameField` — подхватила режим сама).

## Детект хоста

`DetectConptyHost()` в `ProgramSettings()`, по приоритету:

1. `GetEnvironmentVariableW(L"WT_SESSION")` — переменную задаёт WT всем хостируемым процессам (задокументировано в WT);
2. `TERM_PROGRAM == WindowsTerminal`;
3. класс окна консоли: `GetClassNameW` == `PseudoConsoleWindow` (класс conpty; у классической консоли — `ConsoleWindowClass`).

Третий уровень добавлен после диагностики: при запуске **с повышенными правами** UAC пересобирает окружение и обе переменные не пробрасываются, хотя процесс реально в WT. Класс окна не зависит от окружения и покрывает все conpty-хосты.

Обход дерева предков (вариант, который пробовали первым) отброшен: 32-битный процесс + MSIX-упаковка WT мешали `OpenProcess`, а класс окна проще и надёжнее.

## Ключевые решения (почему)

1. **В Adaptive не трогаем шрифт.** Принудительная смена шрифта на 24px через `SetCurrentConsoleFontEx` в conpty сбрасывает буфер к дефолтным 80×25 (установлено тестом). Отсюда в WT нет «поля под 24px» — ограничение хоста, принимаем: поле корректно рисуется с любым шрифтом (просто плотнее/реже). Проверку шрифта в `CheckWindowParameters` убрали по той же причине.
2. **В Adaptive включена двойная буферизация** (обновление). Первая версия рисовала напрямую в видимый буфер — truecolor-заставка «раскатывалась» по строкам (терминал рендерит VT-поток инкрементально), был «рулон» и мерцание. Теперь схема как в Fixed: `wcout`/stdout пишет в `basicBuffer` **независимо от активного буфера** (на этом и работает Fixed), поэтому `DoubleBufferingBegin` показывает предыдущий кадр в `doubleBuffer` и активирует его, новый кадр рисуется в скрытый `basicBuffer`, `DoubleBufferingEnd` переключает активный буфер на `basicBuffer` — атомарная смена кадра. Нюанс truecolor: CHAR_INFO-копия теряет 24-бит, поэтому предыдущий truecolor-кадр показывается через `WriteConsoleW` с сохранённой VT-строкой (`prevFrame`), а 16-цветный — через CHAR_INFO-копию (как в Fixed). VT включён на обоих буферах.
3. **В Adaptive не форсируем размер буфера.** В WT буфер следует за окном (установлено тестом). Форсирование 80×25 при окне 50×15 давало скролл, и подсказка о размере не срабатывала. Отсюда — и ранний `mode con cols=80 lines=25` в `ProgramSettings()` (введён для фикса стартового мерцания в Fixed, см. `Plan.md`) выполняется **только в Fixed**: в Adaptive он ломает рендер (принудительный 80×25 против размера окна). Детект режима и флаги `--adaptive`/`--fixed` потому подняты в `ProgramSettings()` выше создания `doubleBuffer`.
4. **Центрирование кадра.** `frameOffset = (bufW−80)/2, (bufH−25)/2` (если буфер меньше — 0, кадр обрезается справа/снизу). В `ViewGameField` — `SetConsoleCursorPosition` на `(frameOffset.X, frameOffset.Y+row)` перед каждой строкой, обрезка строки по ширине буфера, пропуск строк, выходящих за низ буфера (иначе `wcout` перенесёт хвост на следующую строку и кадр «поедет»). Кадр по-прежнему 80×25, игровая логика и раскладка не меняются.
5. **Очистка буферов при ресайзе и после паузы.** `UpdateAdaptiveBuffer()` перечитывает фактический размер, пересчитывает смещение и при ресайзе ресайзит `doubleBuffer` под фактический размер (он отдельный и за окном не следует) и очищает оба буфера `FillConsoleOutputCharacterW`. `prevFrame` при этом **не** сбрасывается: `ShowPrevFrame` перерисует старый кадр (со старым смещением) в `doubleBuffer`, и экран не станет пустым на кадре ресайза (иначе — мерцание при увеличении окна). Старый кадр живёт ровно один кадр, затем заменяется новым (`prevFrame` обновляется в `ViewGameField`), поэтому артефакта не остаётся. `ClearConsoleBuffer()` (no-op в Fixed) очищает оба буфера и вызывается при возврате из паузы (`MenuResult::Stay`): кадр центрируется и не покрывает весь буфер, поэтому текст меню паузы в левом верхнем углу оставался бы видимым.
6. **Подсказка при маленьком окне — `MessageBoxW`** (`CheckWindowParameters`, только Adaptive): окно < 80×25 — «Увеличьте окно консоли хотя бы до 80x25 — поле будет обрезано». Диалог, а не строка в консоли: в маленьком окне строка обрезается вьюпортом.
7. **Игра в Adaptive рендерится truecolor, а не ANSI 16.** Все игровые кадры вызывают `ViewGameField(frame, true)`: и обычные кадры (`CreateGameField`), и кадры анимации стирания линий (`ClearLines` — там `ViewGameField` вызывается на каждом шаге сдвига). В Adaptive кадр собирается truecolor-последовательностями (`ESC[38;2;R;G;Bm`, палитра `kColorRgb` — классическая палитра Tetris). Иначе цвета фигур шли бы ANSI 16 (`ESC[38;5;Nm`) — палитрой *терминала*, которая расходится с классической палитрой и с цветами заставки (заставка truecolor): на момент стирания линий цвета «прыгали» (кадры стирания ANSI 16, обычные кадры truecolor). В Fixed (conhost) truecolor недоступен — там 16-цветный путь через `SetConsoleTextAttribute`, как и раньше.

## Что проверено

- Сборка — без ошибок и предупреждений.
- Детект: WT → `PseudoConsoleWindow` → Adaptive (в т.ч. с повышенными правами), conhost → `ConsoleWindowClass` → Fixed.
- Центрирование: окно 120×30 и выше — кадр по центру.
- Ресайз окна во время игры — картинка нормализуется, без мерцания.
- Маленькое окно (50×15) — подсказка `MessageBoxW`; проверка шрифта не срабатывает.
- Пауза: после «Продолжить» меню не остаётся на экране.
- Двойная буферизация (Adaptive): заставка появляется атомарно (без «рулона»/мерцания), игровой цикл без мерцания, ресайз окна во время игры — без артефактов.
- Truecolor в игре (Adaptive): цвета фигур совпадают с заставкой и с классической палитрой; при стирании линий цвета не «прыгают» (кадры стирания тоже truecolor).
- Стартовое мерцание в Fixed (conhost): ушло, ресайз не нужен; Adaptive не затронут (ранний `mode con` только в Fixed).

## Ограничения / отложено

- Масштабирование кадра не делаем: окно уже 80 колонок — обрезка (см. `Plan.md`, «Масштабирование кадра — отложено»).
- Заставка в окне < 80×25 урезана (см. `Plan.md`, «Заставка в маленьком окне (Adaptive) — отложено»).
- Диагностические флаги `--adaptive`/`--fixed`/`--diag` оставлены про запас (см. `Plan.md`, «Диагностические флаги — оставлено про запас»).
